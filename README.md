# GF2 Gacha Tracker

《少女前線 2：追放》本地抽卡紀錄與統計工具。

將定向採購、軍備提升、常規採購、自選卡池與特殊招募的紀錄集中整理，提供卡池總覽、菁英時間軸、個別 UP 成本、人形與專武進度等分析。所有個人抽卡資料皆保存在本機。

> 本專案為玩家製作的非官方工具，與 SUNBORN／散爆網路無關。

## 主要功能

### 統計總覽

- 定向採購、軍備提升與常規採購統計
- 總抽數、菁英總數、平均菁英抽數與 UP 率
- 最歐、最非及抽歪紀錄
- 自選人形、自選武器卡池支援

### 特殊紀錄

- 最大連續不歪與最大連續抽歪
- 最歐十連紀錄
- 最歐／最非 6＋1
- 最歐／最非 6＋6
- 一發入魂、十抽奇蹟、驚險壓線與最常來訪
- 閃電出貨、壓線登場、常駐之緣與真愛投入排行榜

### 招募歷史

- 依卡池切換菁英時間軸
- 顯示每次出貨使用抽數、角色／武器名稱及時間
- 顯示目前墊抽與歷史出貨效率

### UP 抽卡分析

- 同角色復刻卡池合併統計
- 自選池紀錄與定向／軍備池進度整合
- 個別人形與武器的菁英機率、平均抽數及 UP 率
- 記錄取得本體、椎體、專武與調校等級所使用的抽數
- 人形＋專武整合進度與目前累計總抽數
- 依 `signatureMap.json` 自動配對人形與專武

### 特殊招募

- 新裝採購同步、限定／稀有衣裝與獎品分類分析
- 神秘箱限定／稀有獎品與碎片換算抽數
- 2026-09「睡醒的人魚／黑桃愛麗絲」物件資料

### 資料管理

- 從遊戲抽卡紀錄 API 同步
- JSON 備份匯入／匯出
- gfl2help JSON 匯入、伺服器選擇、預覽、備份與去重
- 舊資料相容與紀錄去重
- 手動補登早期歷史資料
- 線上更新 `itemMap.json`
- 透過更新清單同步資料表、新卡池設定與美術資源
- 檢查程式新版本

### 多帳號

- 以「伺服器＋UID」識別帳號，可另外設定顯示名稱
- 每個帳號獨立保存抽卡紀錄、同步網址與 Authorization
- 左側帳號按鈕可切換、新增、編輯或移除帳號
- 匯入、匯出、同步、手動補登與清除紀錄只會影響目前帳號
- 舊版單帳號資料會在首次啟動 v2.1.0 時自動建立為「原有帳號」

## 下載與安裝

請前往 [Releases](https://github.com/shrsheng/GF2-Gacha-Tracker/releases) 下載最新的 Windows 安裝程式。

1. 下載 `GF2 Gacha Tracker Setup x.x.x.exe`。
2. 執行安裝程式。
3. 開啟工具並進入「同步設定」。
4. 填入自己的 `gachaUrl` 與 `Authorization` 後更新資料。

> `Authorization` 屬於個人登入資訊，請勿截圖、公開或提供給其他人。

## 資料保存與備份

抽卡紀錄與同步設定皆保存在使用者電腦，不會提交到此 GitHub 儲存庫。更新程式通常不會刪除既有資料，但仍建議在大量補登、換電腦或更新版本前使用：

```text
匯入／匯出 → 匯出 JSON
```

v2.1.0 會自動將舊版 `gacha.json` 與 `config.json` 搬入多帳號資料庫，不會刪除原檔；之後亦會將目前帳號同步成舊格式，方便必要時暫時回退舊版。舊版只能顯示最後使用的帳號，無法管理新版建立的多個帳號。

匯出 JSON 只包含目前帳號。移除帳號不會自動備份，請先切換至該帳號並匯出 JSON。

## 匯入 gfl2help 紀錄

從 gfl2help 匯出的抽卡紀錄可透過「匯入／匯出 → 匯入備份／gfl2help」直接加入。

- 多伺服器資料會先要求選擇匯入來源。
- 匯入前會顯示可匯入筆數與未知道具數量。
- 程式會先自動備份目前紀錄，再執行合併。
- 已存在的紀錄會跳過，本機獨有紀錄不會被刪除或覆蓋。
- 神秘箱與新裝採購的稀有度以本程式物件表重新判斷，不直接採用外部檔案的 `quality`。

## 更新資料表與美術

使用者可從「匯入／匯出 → 更新資料表與美術」取得 GitHub 上的新內容，不必重新下載安裝程式。更新完成後畫面會立即重新載入。

遠端更新由專案根目錄的 `data-update-manifest.json` 控制，可包含：

- `itemMap.json`
- `outfitPoolMap.json`
- `characterArtMap.json`
- `weaponArtMap.json`
- `signatureMap.json`
- `assets` 內新增的 PNG、JPG 或 WebP 圖片

每次新增資料時，將檔案提交到 GitHub，再更新 manifest 的 `version`、`files` 與 SHA-256。程式會先下載並驗證全部檔案，成功後才寫入使用者資料夾；下載中斷或校驗失敗不會覆蓋現有內容。

## 手動補登歷史紀錄

官方 API 只能取得一定期間內的抽卡紀錄。如果曾自行保存更早的出貨資料，可以利用手動模板補進統計。

### 操作方式

1. 選擇「匯入／匯出」。
2. 點擊「下載手動模板」。
3. 使用文字編輯器填寫歷史資料並保存為 JSON。
4. 點擊「匯入手動紀錄」並選擇檔案。
5. 確認新增、重複與跳過筆數。

### 完整逐抽紀錄

```json
[
  {
    "time": "2025-01-01 12:00:00",
    "source": "定向採購",
    "type": "人形",
    "name": "黛煙",
    "rarity": "橙色"
  },
  {
    "time": "2025-01-01 12:00:01",
    "source": "定向採購",
    "type": "武器",
    "name": "舊式武器名稱",
    "rarity": "紫色"
  }
]
```

### 只補登橙色出貨

如果沒有保存逐抽紀錄，可以使用 `pullCount` 填寫該次橙色出貨所花費的抽數：

```json
[
  {
    "time": "2025-01-01 12:00:00",
    "source": "定向採購",
    "type": "人形",
    "name": "黛煙",
    "rarity": "橙色",
    "pullCount": 80
  }
]
```

這筆資料代表黛煙於該輪第 80 抽取得。

若先歪出常駐角色，再取得 UP 角色，請依實際出貨順序填寫：

```json
[
  {
    "time": "2025-01-01 12:00:00",
    "source": "定向採購",
    "type": "人形",
    "name": "維普蕾",
    "rarity": "橙色",
    "pullCount": 65
  },
  {
    "time": "2025-01-02 12:00:00",
    "source": "定向採購",
    "type": "人形",
    "name": "M200",
    "rarity": "橙色",
    "pullCount": 70
  }
]
```

程式會將兩位 UP 角色之間的非 UP 橙色視為歪角。上述範例會統計為 M200 共花費 135 抽，並在過程中於 65 抽歪出維普蕾。

### 欄位說明

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `time` | 是 | 抽卡時間，格式為 `YYYY-MM-DD HH:mm:ss` |
| `source` | 是 | 定向採購、軍備提升、常規採購、自選人形或自選武器 |
| `type` | 是 | 人形或武器 |
| `name` | 是 | 遊戲內顯示的人形或武器名稱 |
| `rarity` | 是 | 橙色、紫色或藍色 |
| `pullCount` | 否 | 該次橙色出貨所花費的抽數，必須為正整數 |

### 匯入規則

- API 同步紀錄優先於手動資料。
- 落在目前 API 已同步日期範圍內的手動資料會自動跳過。
- 手動匯入不會覆蓋或修改 API 紀錄。
- 缺少必要欄位或格式錯誤的資料會跳過。
- `pullCount` 補登資料會參與統計與招募歷史分析，但不會展開成大量虛構的逐抽紀錄。

## 已測試環境

- Windows 10／11
- Haoplay 亞服

其他伺服器理論上可使用，但尚未完整測試。

## 注意事項

- 本工具只會讀取抽卡紀錄 API，不會修改遊戲帳號或遊戲資料。
- 請勿公開自己的 `Authorization`、同步網址或完整設定截圖。
- 官方 API 可查詢的歷史期間可能隨版本調整。
- 遊戲更新後若出現未知人形或武器，可先使用程式內的資料表更新功能。
